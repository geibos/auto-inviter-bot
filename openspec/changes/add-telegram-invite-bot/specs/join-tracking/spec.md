# join-tracking

## ADDED Requirements

### Requirement: Подписка на события вступления

Бот SHALL получать апдейты `chat_member` (тип явно включён в `allowed_updates` long-polling-запросов) и при старте SHALL логировать фактически запрошенный набор `allowed_updates`.

#### Scenario: Запуск бота

- **WHEN** бот запускается и начинает long polling
- **THEN** в `allowed_updates` присутствует `chat_member`, и набор зафиксирован в логе

### Requirement: Фиксация вступления по персональной ссылке

При событии `chat_member` в привязанной группе с переходом в статус участника и полем `invite_link`, совпадающим с активной ссылкой реестра, бот SHALL: пометить запись как «вступил» (сохранив `user_id`, имя и фамилию из профиля, фактический username и время), пометить ссылку использованной и отозвать её через `revokeChatInviteLink`.

#### Scenario: Кандидат вступает по своей ссылке

- **WHEN** пользователь вступает в группу по ссылке записи «Сокол»
- **THEN** запись «Сокол» получает статус «вступил» с `user_id` и временем, а ссылка отзывается

#### Scenario: Вступление по неизвестной ссылке

- **WHEN** пользователь вступает по ссылке, не принадлежащей реестру бота (например, ссылке другого админа)
- **THEN** реестр не изменяется

### Requirement: Фиксация расхождения username

Если фактический username вступившего отличается от username записи реестра, бот SHALL сохранить фактическое значение рядом с ожидаемым; расхождение SHALL быть видно в `/list`.

#### Scenario: По ссылке вступил не тот аккаунт

- **WHEN** по ссылке записи «Сокол» (username `ivan`) вступает пользователь с username `someone_else`
- **THEN** запись помечена вступившей, в `/list` видны и ожидаемый `ivan`, и фактический `someone_else`
