# invite-link-issuance

## ADDED Requirements

### Requirement: Параметры персональной ссылки

Каждая invite-ссылка SHALL создаваться через `createChatInviteLink` в привязанной группе с `member_limit=1` и `name`, равным позывному записи, обрезанным до 32 символов (лимит Bot API).

#### Scenario: Создание ссылки для записи

- **WHEN** для записи «Сокол» создаётся ссылка
- **THEN** вызывается `createChatInviteLink(chat_id, name="Сокол", member_limit=1)` и возвращённая ссылка сохраняется в БД с привязкой к записи

#### Scenario: Группа не привязана

- **WHEN** требуется создать ссылку, но активной привязки группы нет
- **THEN** ссылка не создаётся и инициатор получает понятное сообщение об отсутствии привязанной группы

### Requirement: Не более одной активной ссылки на запись

Бот SHALL поддерживать инвариант: на запись реестра существует не более одной активной (не отозванной и не использованной) ссылки. Все операции получения ссылки MUST переиспользовать существующую активную ссылку (get-or-create).

#### Scenario: Повторный запрос ссылки

- **WHEN** для записи с уже существующей активной ссылкой запрашивается ссылка (например, повторный inline-запрос)
- **THEN** возвращается существующая ссылка, новая НЕ создаётся

### Requirement: Предсоздание ссылки при добавлении записи

При создании записи реестра в момент, когда группа привязана, бот SHALL сразу создать для неё invite-ссылку.

#### Scenario: Добавление записи при привязанной группе

- **WHEN** оператор добавляет запись (через `/add` или bulk-загрузку) и группа привязана
- **THEN** ссылка создаётся немедленно и запись получает статус «ссылка выдана»

#### Scenario: Добавление записи до привязки группы

- **WHEN** оператор добавляет запись, а группа ещё не привязана
- **THEN** запись создаётся без ссылки; ссылка будет создана лениво при первом запросе после привязки

### Requirement: Перевыпуск ссылки

Бот SHALL по команде `/reissue <позывной>` отзывать текущую активную ссылку записи (если есть) и создавать новую. Перевыпуск MUST быть доступен и для записей со статусом «вступил» (повторное приглашение).

#### Scenario: Перевыпуск скомпрометированной ссылки

- **WHEN** оператор отправляет `/reissue Сокол` для записи с активной ссылкой
- **THEN** старая ссылка отзывается, создаётся новая с тем же именем, бот отвечает новой ссылкой
