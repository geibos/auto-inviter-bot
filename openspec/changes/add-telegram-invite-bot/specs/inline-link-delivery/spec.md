# inline-link-delivery

## ADDED Requirements

### Requirement: Поиск записей по inline-запросу

Бот SHALL отвечать на inline-запрос оператора списком до 10 записей, чей позывной или username содержит текст запроса (без учёта регистра). Пустой запрос SHALL возвращать первые записи, ещё не вступившие в группу. Ответ MUST использовать `is_personal=true` и `cache_time` не более 5 секунд.

#### Scenario: Поиск по части позывного

- **WHEN** оператор набирает `@bot сок` в любом чате
- **THEN** бот возвращает карточки записей, чей позывной или username содержит «сок» (например, «Сокол»)

#### Scenario: Пустой запрос

- **WHEN** оператор набирает `@bot ` без текста
- **THEN** бот возвращает до 10 невступивших записей

### Requirement: Карточка результата и отправляемое сообщение

Каждый inline-результат SHALL быть `InlineQueryResultArticle` с заголовком-позывным и описанием (username и статус; для вступивших — «Имя Фамилия (@username)»). Выбор результата для невступившей записи SHALL отправлять в текущий чат сообщение с персональной invite-ссылкой этой записи (get-or-create на этапе формирования ответа). Текст отправляемого приглашения MUST NOT содержать внутренних идентификаторов (позывной, «Гость-N») — нейтральное «Личное приглашение в группу» со ссылкой.

#### Scenario: Выдача ссылки кандидату

- **WHEN** оператор в личном чате с кандидатом выбирает карточку «Сокол»
- **THEN** в чат отправляется сообщение с персональной одноразовой ссылкой записи «Сокол», без позывного в тексте

#### Scenario: Запись уже вступила

- **WHEN** оператор выбирает карточку записи со статусом «вступил»
- **THEN** отправляемое сообщение сообщает, что участник уже в группе, и НЕ содержит invite-ссылки (новая ссылка — только явным `/reissue`)

### Requirement: Создание записи налету через карточку

При валидном запросе `позывной [@username]`, не имеющем точного совпадения по позывному, бот SHALL добавлять к результатам карточку «Создать». Выбор карточки отправляет в чат сообщение-заглушку; по событию `chosen_inline_result` бот SHALL создать запись (создатель — выбравший оператор) и персональную ссылку, после чего отредактировать отправленное сообщение через `inline_message_id`, подставив ссылку. Сами inline-запросы MUST NOT создавать записей — создание происходит только по явному выбору карточки. Существующая запись MUST переиспользоваться: повторный выбор не создаёт ни дубликата, ни новой ссылки.

#### Scenario: Создание по карточке

- **WHEN** оператор набирает `@bot Новичок` (записи нет) и выбирает карточку «Создать „Новичок"»
- **THEN** в чат уходит заглушка, бот создаёт запись и ссылку и редактирует сообщение — в нём персональная одноразовая ссылка

#### Scenario: Точное совпадение — карточки «Создать» нет

- **WHEN** запрос точно совпадает с существующим позывным
- **THEN** карточка «Создать» не показывается — только карточка существующей записи

#### Scenario: Набор без выбора ничего не создаёт

- **WHEN** оператор печатает запрос и закрывает inline, не выбрав карточку
- **THEN** записи и ссылки не создаются

#### Scenario: Повторный выбор той же карточки

- **WHEN** карточка «Создать „Новичок"» выбрана повторно (второе сообщение)
- **THEN** запись не дублируется; отредактированное сообщение содержит ту же активную ссылку

### Requirement: Анонимная ссылка по умолчанию (без позывного)

При пустом запросе первая карточка SHALL быть «Новая ссылка». Её выбор отправляет заглушку; по `chosen_inline_result` бот создаёт запись с автоматическим позывным «Гость-N» (наименьший свободный номер в группе) и персональную ссылку, редактируя сообщение. Каждый выбор карточки SHALL создавать нового гостя (выбор — осознанное действие, в отличие от повторов запроса).

#### Scenario: Выдача анонимной ссылки

- **WHEN** оператор набирает `@bot ` (пустой запрос) и выбирает первую карточку «Новая ссылка»
- **THEN** создаётся запись «Гость-N» со ссылкой, сообщение отредактировано и содержит ссылку

#### Scenario: Два выбора — два гостя

- **WHEN** карточка «Новая ссылка» выбрана дважды (два сообщения)
- **THEN** созданы «Гость-N» и «Гость-(N+1)» с разными ссылками

### Requirement: Зависимость карточек создания от inline feedback

Создание по карточкам работает только при включённом inline feedback (`/setinlinefeedback` → Enabled у BotFather): без него `chosen_inline_result` не доставляется и заглушка не редактируется. Текст заглушки SHALL позволять оператору распознать проблему, а требование к настройке SHALL быть задокументировано в README.

#### Scenario: Feedback выключен

- **WHEN** inline feedback бота выключен и оператор выбирает карточку «Создать»/«Новая ссылка»
- **THEN** сообщение остаётся заглушкой «⏳ Готовлю приглашение…»; README описывает решение

### Requirement: Inline недоступен не-операторам

На inline-запросы пользователей, не являющихся операторами, бот SHALL отвечать пустым списком результатов, не раскрывая содержимое реестра.

#### Scenario: Чужой пользователь вызывает inline

- **WHEN** пользователь, не являющийся админом привязанной группы, набирает `@bot сокол`
- **THEN** бот возвращает пустой список результатов
