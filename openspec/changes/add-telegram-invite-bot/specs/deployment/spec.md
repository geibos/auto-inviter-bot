# deployment

## ADDED Requirements

### Requirement: Конфигурация одним токеном

Бот SHALL запускаться с единственной обязательной переменной окружения `BOT_TOKEN`. Путь к БД SHALL иметь рабочий дефолт (`/data/bot.db` в контейнере, локальный файл при `cargo run`) с переопределением через `DATABASE_PATH`. Миграции схемы SHALL применяться автоматически при старте.

#### Scenario: Первый запуск с чистым томом

- **WHEN** контейнер запущен с заданным `BOT_TOKEN` и пустым volume
- **THEN** БД создаётся, миграции применяются, бот выходит на long polling без дополнительной настройки

#### Scenario: Запуск без токена

- **WHEN** `BOT_TOKEN` не задан
- **THEN** процесс завершается сразу с понятным сообщением об отсутствии токена

### Requirement: Docker-образ и compose

Проект SHALL собираться multi-stage Dockerfile в статический musl-бинарь с минимальным рантайм-образом и поставляться с `docker-compose.yml`: `restart: unless-stopped`, `env_file`, volume для каталога данных, без публикуемых портов (long polling).

#### Scenario: Развёртывание на сервере

- **WHEN** на сервере в каталоге проекта выполняется `docker compose up -d --build` при заполненном `.env`
- **THEN** контейнер собирается, запускается и работает без открытых входящих портов

#### Scenario: Перезапуск контейнера

- **WHEN** контейнер пересоздаётся (`docker compose up -d --build` поверх работающего)
- **THEN** реестр, привязка группы и история ссылок сохраняются (БД в volume)

### Requirement: Локальный запуск для тестов

Бот SHALL запускаться локально командой `cargo run` с `BOT_TOKEN` из окружения или `.env`-файла.

#### Scenario: Локальная отладка

- **WHEN** разработчик выполняет `cargo run` с тестовым токеном в `.env`
- **THEN** бот работает против тестовой группы без Docker
