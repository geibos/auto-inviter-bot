# operator-access-control

## ADDED Requirements

### Requirement: Определение оператора

Бот SHALL считать пользователя оператором тогда и только тогда, когда его статус в привязанной группе (по `getChatMember`) — `creator` или `administrator`. Результат проверки MUST кэшироваться не дольше 60 секунд.

#### Scenario: Админ группы выполняет команду

- **WHEN** администратор привязанной группы отправляет `/list` в личку бота
- **THEN** команда выполняется

#### Scenario: Разжалованный админ теряет доступ

- **WHEN** пользователь лишён админских прав в группе и срок кэша его проверки истёк
- **THEN** его команды получают отказ, а inline-запросы — пустой ответ

### Requirement: Защита всех поверхностей

Все операции бота — команды в личке, bulk-загрузка и inline-запросы — SHALL проверять статус оператора до выполнения. Не-операторам команды MUST получать ответ об отсутствии доступа, а некомандные сообщения MUST игнорироваться без разбора.

#### Scenario: Посторонний пишет боту в личку

- **WHEN** пользователь, не являющийся оператором, отправляет боту `/add Сокол` или произвольный текст
- **THEN** запись не создаётся; на команду бот отвечает отказом, текст игнорируется

#### Scenario: Группа не привязана

- **WHEN** любой пользователь обращается к боту до привязки группы
- **THEN** операторская проверка невозможна; бот отвечает инструкцией по привязке (добавить в группу админом) и не выполняет операций с реестром
