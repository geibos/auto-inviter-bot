# roster-management

## ADDED Requirements

### Requirement: Добавление записи командой /add

Бот SHALL принимать от оператора в личном чате команду `/add <позывной> [@username]` и создавать запись реестра. Позывной MUST быть уникален в пределах группы без учёта регистра; `@` перед username опционален.

#### Scenario: Успешное добавление

- **WHEN** оператор отправляет `/add Сокол @ivan_petrov` в личку бота
- **THEN** создаётся запись (позывной «Сокол», username «ivan_petrov») и бот подтверждает добавление

#### Scenario: Дубликат позывного

- **WHEN** оператор отправляет `/add сокол` при существующей записи «Сокол»
- **THEN** запись не создаётся, бот сообщает о существующей записи и её статусе

### Requirement: Bulk-загрузка многострочным сообщением

Бот SHALL разбирать любое некомандное текстовое сообщение от оператора в личном чате как список записей: одна запись на строку в формате `позывной [@username]`, разделители внутри строки — пробелы, табы, `;`, `,`. После разбора бот SHALL ответить сводкой: добавлено, пропущено как дубликаты, некорректные строки с их номерами.

#### Scenario: Валидный список

- **WHEN** оператор присылает сообщение из трёх строк: `Сокол @ivan`, `Беркут; @petr`, `Ястреб`
- **THEN** создаются три записи и бот отвечает сводкой «добавлено: 3»

#### Scenario: Список с дубликатами и битыми строками

- **WHEN** оператор присылает список, где часть позывных уже существует, а одна строка содержит только `@username` без позывного
- **THEN** новые записи создаются, дубликаты пропускаются, и сводка перечисляет номера некорректных строк и пропущенные дубликаты

### Requirement: Просмотр реестра

Бот SHALL по команде `/list` показывать оператору все записи: позывной, username, статус (ожидает / ссылка выдана / вступил) и для вступивших — дату вступления и фактическую личность вступившего в формате «Имя Фамилия (@username)» (из профиля Telegram на момент вступления). Если список не помещается в одно сообщение Telegram, бот SHALL разбить вывод на несколько сообщений.

#### Scenario: Просмотр смешанного реестра

- **WHEN** оператор отправляет `/list` при наличии записей во всех трёх статусах
- **THEN** бот выводит каждую запись с её статусом, а для вступивших — дату и «Имя Фамилия (@username)»

### Requirement: Удаление записи

Бот SHALL по команде `/del <позывной>` удалять запись реестра и отзывать её активную invite-ссылку, если она существует.

#### Scenario: Удаление записи с активной ссылкой

- **WHEN** оператор отправляет `/del Сокол` для записи с активной ссылкой
- **THEN** ссылка отзывается через `revokeChatInviteLink`, запись удаляется, бот подтверждает
