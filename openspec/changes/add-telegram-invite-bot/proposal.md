# Add Telegram Invite Bot

## Why

Нужен контролируемый способ приглашать людей в закрытую Telegram-группу: каждому кандидату — персональная одноразовая invite-ссылка, привязанная к его позывному, чтобы в настройках группы («Invite Links») было видно, кто по какой ссылке вошёл. Сейчас это делается вручную и не отслеживается.

Исследование Telegram Bot API (10.0, май 2026) подтвердило: inline-бот **не может** определить конкретный чат, из которого его вызвали — объект `InlineQuery` содержит только `chat_type` (sender/private/group/supergroup/channel), без chat id и без идентичности собеседника. Поэтому единственный рабочий UX — оператор передаёт позывной аргументом inline-запроса: `@bot <позывной>`.

## What Changes

- Новый проект: Telegram-бот на Rust (teloxide 0.17), состояние в SQLite, деплой в Docker (long polling, без открытых портов).
- Бот привязывается к группе, в которую его добавили админом с правом `can_invite_users` (v1 — одна группа; схема данных сразу готова к нескольким).
- Реестр кандидатов (позывной + опциональный @username) загружается операторами в личке бота: `/add` для одиночных записей и bulk-загрузка многострочным сообщением (по записи на строку).
- Для каждой записи реестра бот создаёт **одну активную** одноразовую ссылку (`createChatInviteLink`, `member_limit=1`, `name=<позывной>` — имя видно админам в списке invite-ссылок группы).
- Inline-выдача: оператор в любом чате (обычно в личке с кандидатом) набирает `@bot <позывной>`, выбирает результат — в чат уходит сообщение с персональной ссылкой.
- Quick-add налету: запрос `@bot <позывной>[ @username]+` создаёт запись (если её нет) и сразу выдаёт персональную ссылку — без предварительного `/add`.
- Доступ: операторы = администраторы привязанной группы (проверка через `getChatMember`, с кэшем). Любые другие пользователи игнорируются — иначе кто угодно мог бы генерировать приглашения.
- Трекинг вступлений: бот слушает `chat_member`-апдейты (явно в `allowed_updates`), сопоставляет `invite_link` из события со своим реестром, помечает запись как «вступил» и отзывает ссылку.
- Настройка одним токеном: единственная обязательная переменная окружения `BOT_TOKEN`; привязка группы и список операторов выводятся автоматически.
- Деплой: docker-compose в `~/full_server` на `sobieg@10.216.0.11`; локальный запуск для тестов.

## Capabilities

### New Capabilities

- `group-binding`: привязка бота к целевой группе при добавлении админом; реакция на потерю прав/удаление; отказ от второй группы в v1.
- `roster-management`: реестр кандидатов — команды `/add`, `/del`, `/list`, bulk-загрузка списком строк, статусы записей (ожидает / ссылка выдана / вступил).
- `invite-link-issuance`: создание/переиспользование/отзыв персональных одноразовых ссылок с именем-позывным; инвариант «не более одной активной ссылки на запись».
- `inline-link-delivery`: inline-режим — поиск по позывному/username, выдача карточки с персональной ссылкой в текущий чат.
- `operator-access-control`: авторизация всех операций (команды и inline) по членству в админах привязанной группы, с кэшированием.
- `join-tracking`: обработка `chat_member`-событий, фиксация вступления по ссылке, автоотзыв использованной ссылки.
- `deployment`: Docker-образ (multi-stage, статический musl-бинарь), docker-compose с volume для SQLite, конфигурация одним `BOT_TOKEN`.

## Impact

- Новый код: весь репозиторий (Rust workspace: бот, миграции SQLite, Dockerfile, docker-compose.yml).
- Внешние зависимости: Telegram Bot API (createChatInviteLink, answerInlineQuery, getChatMember, chat_member-апдейты); teloxide 0.17 (покрывает Bot API 9.1 — все нужные методы существуют с Bot API 5.x); sqlx + SQLite.
- Инфраструктура: контейнер на `sobieg@10.216.0.11` в `~/full_server`, исходящие соединения только к api.telegram.org, входящих портов нет.
- Ручная настройка вне кода: создать бота у BotFather, включить inline-режим (`/setinline`), опционально `/setinlinefeedback` для статистики выбора; добавить бота в группу админом с правом «Invite Users».
