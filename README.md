# auto-inviter-bot

Telegram-бот персональных одноразовых invite-ссылок. Оператор ведёт реестр
«позывной + @username», бот создаёт под каждого именную одноразовую ссылку
в привязанную группу и выдаёт её через inline-режим прямо в чате с кандидатом.
В списке «Invite Links» группы каждая ссылка подписана позывным; вступления
отслеживаются, использованная ссылка отзывается автоматически.

## Настройка бота у @BotFather

1. `/newbot` → получите `BOT_TOKEN`.
2. `/setinline` → выберите бота → задайте placeholder (например, `позывной…`) —
   **без этого inline-режим не работает**.
3. `/setinlinefeedback` → выберите бота → `Enabled` — **обязательно**: на этом
   держится создание записей из inline (карточки «Создать…» и «Новая ссылка»);
   без него отправленная заглушка «⏳ Готовлю приглашение…» никогда не
   превратится в ссылку.

## Запуск

### Docker (рекомендуется)

```bash
cp .env.example .env   # вписать BOT_TOKEN
docker compose up -d --build
docker compose logs -f # убедиться: «запущен как @…»
```

База живёт в `./data/bot.db` (volume) и переживает пересоздание контейнера.

### Локально (для тестов)

```bash
echo 'BOT_TOKEN=...' > .env
cargo run
```

БД по умолчанию — `./bot.db`; переопределяется `DATABASE_PATH`.

## Привязка группы

Добавьте бота в целевую группу и назначьте администратором с правом
**Invite Users** («Пригласительные ссылки»). Бот привяжется автоматически
и подтвердит сообщением. Одна группа на инстанс (v1); вторую группу бот
вежливо покинет.

Операторы = администраторы привязанной группы. Никакой другой настройки нет.

## Использование

В личке бота (только для операторов):

| Команда | Действие |
|---|---|
| `/add <позывной> [@username]` | добавить запись (ссылка создаётся сразу) |
| `/del <позывной>` | удалить запись, отозвать её ссылку |
| `/reissue <позывной>` | перевыпустить ссылку (старая отзывается) |
| `/list` | реестр: ⏳ ожидает / 🔗 выдана / ✅ вступил |
| `/status` | привязка, права бота, счётчики |

**Bulk-загрузка**: пришлите боту список — по записи на строку,
`позывной [@username]`, разделители: пробел, таб, `;`, `,`.

**Выдача ссылки**: в любом чате (обычно в личке с кандидатом) наберите
`@имя_бота позывной`, выберите карточку — в чат уйдёт сообщение с персональной
ссылкой. Inline-бот не может определить чат сам (ограничение Bot API), поэтому
позывной передаётся аргументом.

**Создание налету**: если позывного нет в реестре, среди подсказок появится
карточка «➕ Создать „…"» (`@имя_бота Новичок` или `Новичок @username`) —
выберите её: в чат уйдёт «⏳ Готовлю приглашение…», и бот тут же отредактирует
сообщение, подставив ссылку. Сам набор текста ничего не создаёт — только выбор
карточки.

**Новая ссылка без позывного (вариант по умолчанию)**: пустой запрос
(`@имя_бота` + пробел) предлагает первой карточкой «➕ Новая ссылка» — создаётся
гостевая запись `Гость-N`; она видна в `/list`, вступление трекается как
обычно, а после входа в `/list` появится «Имя Фамилия (@username)» вступившего.
Каждый выбор карточки — новый гость. Текст приглашения нейтральный — без
позывных и «Гость-N».

После вступления по ссылке бот помечает запись «вступил» (с фактическим
username — расхождение с ожидаемым видно в `/list`) и отзывает ссылку:
`member_limit=1` сам по себе не строго одноразов (выход из группы освобождает
слот), авторитетный механизм одноразовости — отзыв.

## Деплой на сервер

```bash
rsync -av --exclude target --exclude data --exclude .env ./ sobieg@10.216.0.11:~/full_server/auto-inviter-bot/
ssh sobieg@10.216.0.11 'cd ~/full_server/auto-inviter-bot && cp -n .env.example .env'
# вписать боевой BOT_TOKEN в ~/full_server/auto-inviter-bot/.env на сервере
ssh sobieg@10.216.0.11 'cd ~/full_server/auto-inviter-bot && docker compose up -d --build'
```

Откат: `docker compose down` + предыдущий образ; данные в `./data` не трогаются.

## Диагностика

- Сообщение зависло на «⏳ Готовлю приглашение…» — у BotFather не включён
  `/setinlinefeedback` → `Enabled` (см. настройку выше).
- `/status` — права бота и активность привязки.
- Лог при старте перечисляет ожидаемые `allowed_updates` (должен быть `chat_member` —
  иначе вступления не трекаются; проверьте, что бот админ).
- `docker compose logs -f` — события привязки, вступлений, отзыва ссылок.
